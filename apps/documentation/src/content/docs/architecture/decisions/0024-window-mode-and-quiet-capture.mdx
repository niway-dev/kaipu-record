## Context

Desktop 0.12.0 shipped three modes (Area, Screen, Frame) behind the contract of ADR 0022.
After using it the owner asked for three things: fold Area into Frame, add "click a window to
capture it, like macOS" on both platforms, and stop opening the editor when the preferences
already save or copy the capture — a small notification instead. The design (Claude Design
"Kaipu Screenshot Modes v2") also moves the mode choice into the overlay, which means the
overlay must be able to switch into Window mode without leaving.

Two mechanisms are new and need a decision a later reader will question: where the window
geometry comes from, since Electron's `desktopCapturer` names windows but never positions
them, and who decides what happens after a capture.

## Decision

1. **Window mode runs on our overlay on both platforms, with the window list from an OS
   scripting tool and no native module.** macOS: `osascript -l JavaScript` calling
   `CGWindowListCopyWindowInfo` (id, owner, title, bounds, layer; 30 ms in a 50 ms process on
   the development Mac). Windows: a PowerShell script over `EnumWindows`,
   `DwmGetWindowAttribute(DWMWA_EXTENDED_FRAME_BOUNDS | DWMWA_CLOAKED)` and `GetWindowLongPtr`,
   converted to DIP with `screen.screenToDipRect`. A `WindowLister` port isolates both; a pure
   function filters (own process, tool and cloaked windows, tiny windows) and assigns displays.
2. **Window pixels are taken by window id, not by screen rect.** macOS `screencapture -l <id>
-o -x`; Windows the `window:<hwnd>` source of `desktopCapturer` at the window's physical
   size. A screen crop at the window rect is the fallback, never the primary path.
3. **Area is removed.** Frame draws a new box from a drag on the sheet and still remembers its
   last one per display. Stored `"area"` migrates to `"frame"`, which becomes the default.
4. **The overlay's action decides, then the preferences.** The selection carries Capture and Copy
   (and a reserved, disabled Record). `decideAfterCapture(action, save, copy)`: Copy always finishes
   quietly (clipboard; vault only when saving is automatic); Capture opens the editor only when saving
   is manual, otherwise main saves, copies if copying is automatic, and shows one always-on-top capture
   toast (Annotate, Open/Save to Library, 6 s) on the display the shot came from. No third preference
   is added.
5. **Record keeps a seat in the action bar.** The overlay is the one "this display or this selection"
   picker; the recording feature reuses it instead of growing a second one.

## Alternatives rejected

- **Apple's own window picker (`screencapture -w`) on macOS.** Free highlight chrome, but it
  replaces our overlay the moment the user switches to Window from the pill, and the pill
  cannot come back. Two picker styles for one feature. Kept as the fallback if the JXA listing
  ever stops working.
- **A native module for window enumeration** (`node-window-manager`, koffi over `user32`).
  Faster on Windows, but a second native dependency with its own Electron ABI rebuild, against
  the repo's native-dependencies rule, for a list a 20-line script already returns. It is the
  escape hatch if PowerShell measures above 800 ms on real hardware.
- **A grid of window thumbnails** (the Teams/Zoom share picker). Needs no geometry, but it is
  not "click the window you are looking at", which is what was asked.
- **A new "after capture" preference.** It would restate what the save and copy toggles already
  say and create a fourth contradictory state ("quiet, but save manual and copy manual" has
  nothing to show in a toast).
- **Let the preferences alone decide, with no Copy in the overlay.** It was the first draft of this
  ADR. The owner wants an explicit "copy and finish" while looking at the selection, and the same
  bar is where Record will live; a bar with one button would be rebuilt within a release.
- **A toast inside the main window.** Forces the main window on screen, which is the thing
  quiet capture exists to avoid.
- **Keep Area as a fourth mode.** Same gesture as Frame with different memory; a fourth entry
  in the pill for no new capability.

## Consequences

- Two more small child-process integrations (`osascript`, `powershell`) with timeouts; a
  stuck or missing tool degrades to "no windows found", not to a stuck overlay.
- The provider now branches on the overlay's answer, not on the requested mode, because the
  mode can change inside the overlay.
- Main gains a vault-write and clipboard path for screenshots that bypasses the editor; the
  editor must recognise `origin: "quiet"` and skip its own auto actions.
- One more floating window kind (`capture-toast`) with the bubble's options and its own
  positioning rules; `desktop/ipc-contract.mdx` gains three channels.
- The default mode changes for every existing user (Area → Frame). The first overlay they see
  is a remembered or default box, not a crosshair.

## Non-goals

- Recording through the overlay (the seat is reserved, the picker is its own design); a thumbnail
  grid; scrolling, OCR, timers, freeze; Linux.
- Any change to the editor's tools or the vault layout.

## Reopen when

- The PowerShell listing measures above 800 ms from shortcut to first highlight on the first
  Windows build (then a native module behind the same port).
- A macOS release removes the JXA bridge or `CGWindowListCopyWindowInfo` stops returning bounds
  without extra permission (then `screencapture -w`).
- Analytics show `after: "quiet"` below one in ten captures three months after shipping: the
  toast stays, but no more work goes into it.
