## Context

The owner wants memory, CPU, duration, output and weight measured for every scenario of the desktop
app: idle, recording, screenshots, editing, long-video editing, playback, export at 1080p and 4K,
and the weight a library or an animation adds. On 2026-11-14 an export held the whole encoded video
in renderer memory (peak 6.5 GB; the owner's sampling CSV, see the spec's sources), and nothing in
the repository measured it.

The question is where the app runs while it is measured. Facts that constrain it:

- **Agents never run Electron on the owner's laptop** (ADR 0044's context).
- **The mini already runs the real app unattended** for the UI catalog: ssh, a launchd job in the
  console session, screen-recording permission granted there.
- **GitHub-hosted macOS runners** are M1 VMs with 3 cores and 7 GB of RAM, without Metal
  Performance Shaders, with no known way to grant screen-recording permission non-interactively,
  and with an unknown WebCodecs encoder path
  ([GitHub docs](https://docs.github.com/en/actions/reference/runners/github-hosted-runners)). The
  repository is public, so their standard minutes are free.
- **GitHub says self-hosted runners "should almost never be used for public repositories"**
  ([security guide](https://docs.github.com/en/actions/reference/security/secure-use)).
- **ADR 0027** gives ordinary pull requests an immediate pass on the required check; the owner wants
  fast merges.
- The owner wants the suite run many times on the mini, and a clean environment on demand.

## Decision

1. **The Mac mini runs the authoritative series**, through `bun run bench:remote` over ssh as a
   launchd job, nightly on `main`, on demand for any ref, and on the desktop release pull request.
   It is never registered as a self-hosted Actions runner.
2. **One host lock** on the mini is shared by benchmarks, the UI catalog and the verify runner. A
   run that cannot take it waits up to a limit or skips and records the skip; a run that overlapped
   another is invalid.
3. **`.github/workflows/benchmarks.yml` runs the suite on demand** (`workflow_dispatch` only) on a
   GitHub-hosted macOS runner, as its own series. Its numbers are never compared with the mini's.
   It runs only the scenarios a spike proves possible there (no recording, no screenshots).
4. **Weight is measured on every pull request** on a hosted runner, as a non-required job that
   updates one sticky comment only when a weight layer changes. The required check of ADR 0027 is
   untouched.

## Alternatives rejected

- **Only hosted runners.** They cannot record the screen or take screenshots, may export through a
  different encoder, and their shared cores make time and CPU noisy. Rejected as the main series;
  kept as the on-demand clean environment.
- **A self-hosted Actions runner on the mini.** It would let workflows reach the owner's machine,
  against GitHub's guidance for public repositories. ssh plus launchd reaches the same app without
  exposing the machine to workflow code.
- **Only the mini, no hosted workflow.** Loses the clean, isolated terrain the owner asked for and
  the free per-pull-request weight measurement.
- **A benchmark that gates ordinary pull requests.** Reverses ADR 0027's fast merges; weight stays
  informative.

## Consequences

- The mini carries a third kind of job; the lock changes `ui-catalog-remote.sh` and the verify
  runner as well.
- There is no series when the mini is off; the nightly records the gap.
- The hosted series needs a token scoped to the results repository, reachable only from
  `workflow_dispatch`, never from a fork pull request.
- A weight comment appears on pull requests that change weight; the owner sees deltas before merge.

## Non-goals

- Windows or Linux performance.
- Running scenarios on the owner's laptop. `bench:attach` (spec) only attaches to an app the owner
  launched.
- Blocking any merge or release (see ADR 0061 for the release status).

## What would reopen this

- GitHub-hosted macOS runners gain screen-recording permission and a real GPU encoder, and their
  run-to-run noise on the mini's metrics is within the mini's own noise: the hosted runner could
  become the main series.
- The mini is replaced, shared with other people, or unavailable for more than a week at a time.
- GitHub offers a safe way to restrict a self-hosted runner on a public repository to trusted
  workflows, and the ssh path becomes a maintenance burden.
