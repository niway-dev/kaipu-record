## Brief

Research task, read-only. Do not edit any file. Answer in English.

Context: Kaipu Record is an Electron desktop screen recorder (macOS Apple Silicon first, Windows later). Each recording has a microphone audio track and a system audio track. We want 100% local speech-to-text with NVIDIA Parakeet (preferred over Whisper because the owner measured better results) to produce (a) subtitles/captions and (b) a full transcript with word-level timestamps, tied to the video. Spanish and English speech both matter.

Question: what are the realistic ways to run Parakeet locally inside an Electron app today, and which one should we pick?

Compare at least these runtimes, reading their repos/docs/issues (cite URLs):

- sherpa-onnx (k2-fsa): Node/N-API addon (sherpa-onnx-node), prebuilt CLI binaries, its Parakeet TDT ONNX exports (int8/fp32), offline recognizer, VAD, timestamps
- FluidAudio (Swift, CoreML / Apple Neural Engine) and how an Electron app could call it (CLI helper binary, Swift sidecar)
- parakeet-mlx (Python MLX) — and whether shipping Python is realistic
- onnx-asr (Python) and transcribe-rs / the Handy app (Rust) as prior art of a desktop app shipping Parakeet
- NVIDIA NeMo reference (for accuracy baseline only)
- For contrast: whisper.cpp and WhisperKit, especially Spanish accuracy vs Parakeet

For each: platforms (macOS arm64, Windows x64), packaging into an Electron app (native addon vs sidecar binary vs utility process; code signing/notarization implications), model files and sizes (Parakeet TDT 0.6B v2 English-only vs v3 multilingual 25 European languages incl. Spanish; int8 vs fp32), speed (real-time factor on Apple Silicon if published), word/token timestamp support, long-audio handling (max duration per pass, chunking/VAD strategy for a 30–60 min recording), memory use, licenses (model CC-BY-4.0 attribution obligations; runtime license), maintenance signals (last release, stars, open issues on timestamps or crashes).

Also answer: does Parakeet v3 auto-detect language per segment? Does it output punctuation and capitalization? How are token timestamps turned into word timestamps? Known accuracy issues (numbers, code terms, short utterances, music/silence hallucination)?

## Report

I’ll compare the shipping options against their current documentation and issue trackers, with particular attention to Spanish, timestamp quality, and Electron packaging.
The main risk is Spanish recognition and chunk boundaries, rather than whether Parakeet can run locally. FluidAudio has addressed several dropped-word and timestamp issues, but a documented Latin American Spanish failure also reproduces in NVIDIA’s reference model, so changing runtimes alone may not fix it.
**Pick sherpa-onnx with Parakeet TDT v3 int8 as the first production backend, isolated in an Electron utility process; keep a signed native sidecar as the fallback packaging route.** It provides one implementation for macOS arm64 and Windows x64, avoids shipping Python, and exposes the tokens and timing needed for captions and transcripts. Benchmark a **FluidAudio Swift helper** alongside it before committing: its ANE acceleration is attractive for macOS, but its CoreML/windowing path has required substantial accuracy repairs. Use NeMo and parakeet-mlx as accuracy references, not initial shipping dependencies. Spanish acceptance tests are essential: v3 supports Spanish, but conversational Latin American Spanish has documented wrong-language substitutions even upstream. [sherpa installation](https://github.com/k2-fsa/sherpa/blob/master/docs/source/onnx/javascript-api/install.rst), [FluidAudio Spanish report](https://github.com/FluidInference/FluidAudio/issues/842)

### Findings

1. **v2 is English-only; v3 supports 25 European languages including Spanish**, so v3 is the appropriate default for Kaipu’s bilingual requirement. [NVIDIA model card](https://huggingface.co/nvidia/parakeet-tdt-0.6b-v3)

2. **v3 automatically recognizes the input language without prompting**, meaning independently submitted segments are independently decoded, but reliable intra-segment code-switching and explicit language labels are not guaranteed—the sherpa sample returns an empty `lang`. [Model card](https://huggingface.co/nvidia/parakeet-tdt-0.6b-v3), [sample output](https://github.com/k2-fsa/sherpa/blob/master/docs/source/onnx/pretrained_models/offline-transducer/code-nemo/sherpa-onnx-nemo-parakeet-tdt-0.6b-v3-int8.txt)

3. **Punctuation and capitalization are native outputs**, while number formatting is a separate concern and FluidAudio offers optional inverse text normalization. [Model card](https://huggingface.co/nvidia/parakeet-tdt-0.6b-v3), [FluidAudio](https://github.com/FluidInference/FluidAudio)

4. **Token timestamps are decoder emission positions, not precise acoustic word boundaries**: transcribe-rs converts frames at 80 ms, groups subwords using spaces/`▁`, and estimates ends from the next token, with a 50 ms final-token fallback. [Implementation](https://github.com/cjpais/transcribe-rs/blob/main/src/onnx/parakeet/mod.rs)

5. **sherpa’s sample returns tokens and timestamps but an empty `words` array**, so implement and validate word grouping rather than assuming every binding supplies finished word intervals. [Published output](https://github.com/k2-fsa/sherpa/blob/master/docs/source/onnx/pretrained_models/offline-transducer/code-nemo/sherpa-onnx-nemo-parakeet-tdt-0.6b-v3-int8.txt)

6. **For 30–60 minutes, use bounded speech chunks**, since onnx-asr recommends VAD above 20–30 seconds and has an open report of a roughly 300-to-600-second input-length cliff. [README](https://github.com/istupakov/onnx-asr), [length issue](https://github.com/istupakov/onnx-asr/issues/131)

7. **FluidAudio’s export/windowing behavior can differ from NeMo or MLX**, with documented dropped/mangled words and blank windows subsequently addressed by recovery and stitching changes. [Window sensitivity](https://github.com/FluidInference/FluidAudio/issues/760), [blank-window repair](https://github.com/FluidInference/FluidAudio/issues/909)

8. **Conversational Latin American Spanish can become English-sounding substitutions**, and the report’s correction confirms upstream fp32 also fails, rather than establishing a CoreML-only translation bug. [Corrected Spanish report](https://github.com/FluidInference/FluidAudio/issues/842)

9. **Silence/noise hallucinations remain possible with Parakeet**, although the MLX report is community evidence rather than a controlled, independently verified benchmark. [Open hallucination report](https://github.com/senstella/parakeet-mlx/issues/46)

10. **Electron packaging needs real native-library validation**: sherpa’s addon requires shared libraries, and generic Electron native-module guidance does not prove a particular N-API prebuild works unchanged in the packaged app. [sherpa installation](https://github.com/k2-fsa/sherpa/blob/master/docs/source/onnx/javascript-api/install.rst), [Electron native modules](https://www.electronjs.org/docs/latest/tutorial/using-native-node-modules)

11. **Ship executable helpers and libraries outside ASAR, sign nested native code and notarize the Mac bundle**, while keeping downloaded model data in writable application storage; this is the recommended integration design, not a verified Kaipu build. [Electron signing guidance](https://www.electronjs.org/docs/latest/tutorial/code-signing)

12. **Preserve model attribution separately from runtime notices**: credit NVIDIA and the conversion source, link the model and CC-BY-4.0, retain supplied notices and indicate conversion/quantization changes. [CC-BY-4.0 terms](https://creativecommons.org/licenses/by/4.0/)

### Open risks and measurements

Use a fixed local corpus of Peruvian/Latin American Spanish, English and code-switching, including numbers, dates, currencies, identifiers, acronyms, short utterances, silence and music; **specific number/code-term error rates and short-utterance failure rates remain unverified**, as does any general Spanish advantage over Whisper.

Compare sherpa int8 against fp32/NeMo, FluidAudio v3 and multilingual Whisper large-v3/turbo; measure word error rate, omissions, language substitutions, timestamp boundary error, cold/warm latency, RTF, peak resident memory and energy use.

For Kaipu, process microphone and system tracks separately, preserve their video-time offsets, and merge timed results with track identity; start with VAD-delimited **15–25-second chunks**, padded boundaries and overlap reconciliation, then test a full hour for missing/duplicated words and drift.

Finally, validate offline operation, cancellation/restart, model checksums/download recovery, Unicode Windows paths, and signed/notarized installation on a clean Mac; no files were edited and no local inference benchmark was run.
