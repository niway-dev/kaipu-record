## Caveats del E2E en Electron

La app vive de cosas que el E2E **no** cubre fácilmente:

- Permiso de **screen recording / audio** de macOS (el prompt nativo no se auto-concede).
- Captura nativa, subproceso **FFmpeg**, **Keychain**.

**Alcance realista:** flujos de UI (auth, navegación, Library, Settings, estados de la state machine con servicios nativos mockeados). El pipeline de captura real **se queda en integration**, no en E2E.

## Alternativa a evaluar

`wdio-electron-service` (WebdriverIO) es el estándar de facto para E2E de Electron — más maduro que Playwright para mockear módulos de Electron y multi-ventana. Si el E2E de Electron crece, comparar antes de comprometerse. Si ya se usa Playwright para `web-recorder`, mantener un solo runner también es argumento válido.

## Pirámide objetivo

- **Unit + integration** → Vitest
- **E2E web** → Playwright
- **E2E Electron** → Playwright (smoke UI) · WebdriverIO si crece
