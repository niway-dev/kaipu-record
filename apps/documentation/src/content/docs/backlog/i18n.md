# i18n — web + desktop (es/en)

> **Status: Stage 1 merged (#31) · 🟢 Stage 2 ready to validate** (`feat/i18n-stage2-propagation`).
> Every web page and every desktop feature is now translated; 600/600 desktop tests pass, both apps
> build. Awaiting owner validation in the running app before merge. Full design:
> [i18n web + desktop — design](/specs/2026-07-06-i18n-web-desktop-design).

Two locales (`es` default, `en`), one shared `@kaipu/i18n` package (use-intl v4), consumed by
both `apps/web-hono` (cookie + SSR) and `apps/kaipu-record` (locale on `AppSettings`, tray + all
renderer windows). Spanish is the source of truth.

## Stages

| Stage             | Scope                                                                                                                                                                                                                 | Status               |
| ----------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------- |
| **1 — Wire**      | `@kaipu/i18n` package + wiring in both apps + switchers + parity/install tests + principal surfaces translated (all of web; desktop shell / settings / record / tray). One large PR.                                  | ✅ Merged (#31)      |
| **2 — Propagate** | Every remaining web page (auth, account, todos) + desktop feature (library, screenshots, video-editor, recording, floating windows, onboarding, shortcuts, updater, version-gate) translated, one commit per feature. | 🟢 Ready to validate |

## Key decisions (vs. the original handoff docs)

- **Reuse `AppSettings`** for desktop persistence — no `electron-store`, no `i18n:*` IPC channels.
- **Tray only** is the native surface (no application menu on this tray-first app).
- **`typeof es` type augmentation**, no codegen; a `es`/`en` parity test guards completeness.
- Shared workspace package is justified because web and desktop share the same message source.
- **Build/consumption:** the package is built with `tsdown` (`exports.devExports` → source in dev,
  `dist` under `publishConfig`); the Electron **main** bundles it (electron-vite
  `externalizeDepsPlugin({ exclude })`) because Node can't load its raw TS. Full pattern:
  [Shared package build & consumption strategy](/architecture/shared-package-build-strategy).
