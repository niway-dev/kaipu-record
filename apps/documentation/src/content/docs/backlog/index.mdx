## Items without their own doc

### Recording pipeline

These come from the audit in [Recording Pipeline → what does not exist yet](/desktop/recording-pipeline). Summary:

- **Hardware encoding** — encoding runs in the renderer today (`MediaRecorder`, VP9+Opus). Moving it to FFmpeg with VideoToolbox/NVENC would free React's thread. FFmpeg is already bundled, so the bundle cost is zero.
- **Native capture** — `getDisplayMedia()` in the renderer today; ScreenCaptureKit (macOS) / Windows.Graphics.Capture would give better performance and fidelity.
- **MP4/H.264 output** — the current output is WebM (except with the webcam). Moving to MP4 through FFmpeg gives universal compatibility for sharing. The disk-streaming IPC already works and does not change.
- **Own benchmark** — there is no measurement of CPU, RAM or dropped frames to validate the improvements above.

## How to use this section

- An item that starts being worked on moves to 🟡 and, if it has substance, gets its own doc (like [playwright-e2e](./playwright-e2e)).
- When an item is done: move what was learned into the matching feature or architecture doc (`desktop/`) and remove it from the map.
- Keep **effort** and **status** current — this is the source of truth for what comes next.
