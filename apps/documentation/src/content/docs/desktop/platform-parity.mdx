title: Platform parity (macOS and Windows)
description: One row per desktop capability — what macOS and Windows each run, whether the code is shared or branched, and what has actually been verified on each platform.
---

**Every PR that adds or changes a `process.platform` branch (or a renderer
`isWindowsHost()` / `formatAccelerator` platform split) updates this table in the same PR.**

The table says what the code does on each platform and how far that has been checked. It is
not a roadmap: work that is planned but not started is `pending`, and nothing moves to a
better status without the verification named in the last column.

## Status legend

| Status       | Meaning                                                                                                  |
| ------------ | -------------------------------------------------------------------------------------------------------- |
| `1:1`        | Same code on both platforms. No `process.platform` branch; what macOS verifies covers Windows too.       |
| `own path`   | A platform branch exists **and** the Windows path has been run on Windows hardware.                      |
| `unverified` | A platform branch exists, but the Windows path has never been run on Windows hardware (only unit tests). |
| `pending`    | Not done on Windows yet.                                                                                 |

"Verified by" names the evidence. **QA-10** is decision 10 of the
[Windows release design](/specs/2026-10-15-windows-release-design/) — the manual QA pass on
real Windows hardware, recorded on the [Windows beta](/backlog/windows-beta/) page. Until that
pass happens, no row is `own path`.

## When a row changes

- A new `process.platform` branch: add or edit the row, status `unverified`.
- Windows hardware QA passes for a branched row: move it to `own path` and name the QA run
  (date, build) in "Verified by".
- A branch is removed and the code becomes shared: `1:1`.
