# Recording Pipeline

> **Estado (2026-06-26).** El grabador de **kaipu-record hoy es un stub**: `startRecording()` solo cambia un booleano tras un countdown — no captura nada (`src/renderer/src/features/recording/hooks/use-recording-setup.ts`). Lo que sigue describe el pipeline del **recorder legacy** (`workspace-temp/legacy-kaipu-recorder`) como referencia técnica. El **target elegido** para construir el core real es **mediabunny, no FFmpeg** — ver [ADR 0001](../architecture/decisions/0001-mediabunny-over-ffmpeg).

Auditoría técnica del pipeline de captura y encode legacy (referencia).

## TL;DR

| Dimensión          | Hoy                                              |
| ------------------ | ------------------------------------------------ |
| Captura            | `getDisplayMedia()` en el renderer               |

## Captura

**Método:** `navigator.mediaDevices.getDisplayMedia()` en el renderer.

Tres estrategias en cascada:

1. Audio con constraints explícitas (`echoCancellation: false`, 48kHz, stereo)
2. `audio: true` simple
3. Solo video como último fallback

El main process usa `desktopCapturer.getSources()` para listar pantallas.

**Archivo:** `src/features/recording/hooks/useMediaRecorder.ts`

---

## Encoder

`MediaRecorder` con:

```
mimeType: 'video/webm;codecs=vp9,opus'
videoBitsPerSecond: 2_500_000  (configurable por settings)
chunk interval: 1000 ms
```

Webcam en paralelo:

```
mimeType: 'video/webm;codecs=vp9'
videoBitsPerSecond: 1_000_000
```

**Encode corre en el renderer** — compite con el thread de React.

---

## Data handling — streaming a disco

**No hay acumulación en memoria.** Anti-OOM para grabaciones largas.

```
ondataavailable → blob → base64 (renderer)
  → IPC recording:append-chunk → main
  → WriteStream (backpressure, 1 MB buffer)
  → archivo temp en app.getPath('temp')
  → al parar: finalize → move → vault del usuario
```

**Archivo:** `src/features/recording/hooks/useMediaRecorder.ts`, `src/main.ts`

---

## Post-procesamiento

**Screen-only:** WebM directo del MediaRecorder → `remuxWebmInPlace` agrega header de duración.

**Con webcam:** MP4 via re-encode FFmpeg post-grabación (`VideoComposer`, CRF 20, 4 threads, target 30fps).

**Thumbnail:** PNG 320×240 extraído al segundo 1, en background (no bloquea).

## Target elegido: mediabunny (no FFmpeg)

La decisión es **no portar** el stack `MediaRecorder` + FFmpeg del legacy, sino construir el core sobre **mediabunny** (WebCodecs). Razón corta: gran parte del rol de FFmpeg en el legacy era **parchear problemas que `MediaRecorder` causa** (WebM sin duration header → remux). mediabunny no usa `MediaRecorder`, así que esos parches no nacen.

Flujo target:

```
getDisplayMedia() ─┐
getUserMedia(mic) ─┤─► MediaStreamVideo/AudioTrackSource
                   └─► Output({ format: Mp4OutputFormat, target: StreamTarget })
                       → MP4 real seekable, escrito a disco incremental (chunk.position)
                       → main: fd.write(data, 0, len, position) vía IPC
```

Qué cambia vs. el legacy:

| Aspecto         | Legacy                          | Target mediabunny                     |
| --------------- | ------------------------------- | ------------------------------------- |
| Encoder         | `MediaRecorder` VP9/Opus        | WebCodecs H.264/AAC (HW, ~8× más rápido) |
| Output          | WebM roto → remux FFmpeg        | MP4 seekable de un solo paso          |
| Hot path a disco| base64 → IPC → WriteStream      | bytes crudos posicionados (`StreamTarget`) |
| Compositing     | FFmpeg `filter_complex`         | canvas + `CanvasSource` en vivo       |
| Bundle          | ~50–80MB binarios por arch      | ~70 kB, tree-shakable, sin deps       |
| FFmpeg          | core del pipeline               | opcional/lazy, solo post-proceso offline |

Detalle completo y alternativas descartadas: [ADR 0001 — Mediabunny over FFmpeg](../architecture/decisions/0001-mediabunny-over-ffmpeg).
