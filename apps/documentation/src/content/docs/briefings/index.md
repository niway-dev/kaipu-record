# Briefings

Six short, self-contained documents that each answer "what is this project?" for a
different reader. Unlike the rest of this site, a briefing is meant to be read (or
pasted) on its own — it doesn't assume you've read anything else here.

- [**Pitch**](./pitch) — for a person deciding whether to try Kaipu Record. The
  problem it solves, what it is, and who it's for.
- [**Roadmap**](./roadmap) — for "what's the state of this, right now?" What shipped,
  what's in flight, what's next.
- [**AI briefing**](./ai-briefing) — for another AI, pasted whole. Everything a model
  needs to answer questions or write code about this project without repo access.
- [**Stack**](./stack) — for a developer evaluating the technical choices. Every
  layer, what it's for here, and why it was picked.
- [**Design brief**](./design-brief) — for an AI (or designer) doing visual work on
  Kaipu. The palette, type scale, and voice, read from the tokens package itself.
- [**Business brief**](./business-brief) — for an AI reasoning about the venture: the
  model, the target user, and the deliberate non-goals.

These are panoramas, not the source of truth for any single decision. For the
reasoning behind a specific architectural choice, see the
[architecture decision records](../architecture/decisions/). For what's actively
being worked on item-by-item, see the [backlog](../backlog/). For what changed in a
specific release, see the [changelog](../changelog).
