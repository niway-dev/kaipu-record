# Contributing to Kaipu Record

Kaipu Record is maintained by **Cristian Sotomayor ([@csdev19](https://github.com/csdev19))**,
its author and lead maintainer, and published by **Niway S.A.C.** under
[AGPL-3.0-only](LICENSE). The roadmap is the maintainer's.

## Issues are welcome. Pull requests are not open to everyone.

Opening an issue is the way to contribute: bug reports, crash reports, feature requests
and questions all start there. **Pull requests are limited to collaborators.** If you are
not one, GitHub will not let you open one, and that is deliberate.

Kaipu is a one-person project. Unreviewed pull requests — increasingly generated by AI
tools — cost more review time than they save, and a desktop app that records people's
screens cannot afford a regression nobody had time to catch. A well-written issue gives the
maintainer everything a pull request would, without the review queue.

### A good bug report

Use the **Bug report** template. It asks for what makes a bug fixable:

- the Kaipu version (Settings → About) and your macOS version;
- what you did, what you expected, and what happened instead;
- a short screen recording or screenshot when the problem is visual.

### A good feature request

Describe the problem you have, not only the feature you want. "I lose my place when I
switch displays mid-recording" is more useful than "add a display switcher".

### Security issues

Never in a public issue. See [SECURITY.md](SECURITY.md).

## For collaborators

- **Sign the [Contributor License Agreement](CLA.md) once, on your first pull request.** You
  keep the copyright to your work; Niway gets a license broad enough to keep the whole project
  under one owner, including the right to change its license later. Without it a pull request
  is not merged. The same applies to code pasted into an issue: it is read as part of the
  report, and merged only once its author has signed.
- **Issue first.** A pull request links the issue it resolves.
- **One behaviour per pull request.** Refactors travel separately.
- **The checks apply to everyone.** The pre-push hook runs lint, format, builds and type
  checks; `bun run verify` runs everything on demand. In Actions, the release pull request
  runs `verify`, the app builds and the macOS end-to-end suite before anything is tagged
  ([ADR 0027](apps/documentation/src/content/docs/architecture/decisions/0027-verify-release-candidates-only.mdx)).
- **Disclose generated code.** Say whether a tool wrote it, and confirm you ran it.
- **No drive-by dependency changes.** A new or upgraded dependency needs its own issue: there
  is no `postinstall`, and native rebuilds are explicit by design.
- English for code, commits, pull requests and docs; Conventional Commits for messages,
  because release-please derives versions from them.

Setup and commands are in the [README](README.md) and the
[documentation site](apps/documentation/src/content/docs/).

## Forks

Forks are welcome — that is what the license is for. Under AGPL-3.0, if you run a modified
version as a network service, you must offer its source to its users. A fork you distribute
uses its own name and icon: the license covers the code, not the Kaipu name or logo
([TRADEMARKS.md](TRADEMARKS.md)).
