# Project

**Kaipu** (`kaipu-record-monorepo`, GitHub `niway-dev/kaipu-record`): a Bun + Turborepo monorepo for **Kaipu Record**, a local-first screen and camera recorder for macOS, plus its cloud backend and web app.

## Purpose

Desktop recorder (Electron) that works local-first. A cloud layer is being added: recordings upload to Cloudflare R2 through an auth-gated oRPC API.

## Stack

- Desktop: Electron + electron-vite + React, Vitest, Playwright e2e, electron-builder (`apps/kaipu-record`)
- API: Hono + oRPC on Cloudflare Workers (wrangler) (`apps/server-hono`)
- Web: TanStack Start + Vite on Workers, deployed with alchemy (`apps/web-hono`)
- Docs: Astro Starlight (`apps/documentation`)
- Data/auth: Postgres (Neon) + Drizzle, Better Auth, R2 via aws4fetch, dotenvx-encrypted env
- Tooling: Bun 1.3.4 workspaces + catalog, Turborepo, oxlint + oxfmt, husky + lint-staged, release-please

## Structure

- `apps/kaipu-record`: Electron app (`src/main`, `src/preload`, `src/renderer`, `src/shared`)
- `apps/server-hono`, `apps/web-hono`, `apps/documentation`
- `packages/domain` is pure and mobile-safe. `packages/application` holds the use cases.
- `packages/infra-{db,auth,storage,cloudflare,env}`: infrastructure
- `packages/web-ui` (its `dist/` is committed), `tokens`, `i18n`, `config`
- `.claude/`: rules, skills, architecture notes. `CLAUDE.md` is the main agent rulebook.

## Commands

- `bun install` / `bun run dev` / `bun run build` / `bun run check-types` / `bun run test`
- `bun run dev:server-hono` / `bun run dev:web-hono`
- Desktop (in `apps/kaipu-record`): `bun run dev`, `test`, `test:e2e` (needs ffmpeg), `typecheck`, `build:mac`
- Lint/format: `bun run lint`, `bun run format`, `bun run check`
- DB (always from the repo root): `bun run db:push | db:generate | db:migrate | db:studio`
- Release: release-please. It opens separate PRs for the components `desktop`, `web` and `api`. Merging a release PR cuts the release. Never publish by hand.

## Agent Rules

- **Read `CLAUDE.md` first.** It has the authoritative rules: MVP-first then refactor, DDD layer rules, the docs policy and known issues.
- Import rules: domain ← application ← infra. Only apps wire the layers together. `infra-*` never imports `application`.
- Every feature gets a doc in `apps/documentation/src/content/docs/` (`backlog/`, `specs/`, `plans/`) and uses the status legend. Docs are in English.
- After changing `packages/web-ui`, rebuild its `dist/`. After editing a `wrangler.jsonc`, run `wrangler types`.
- Use Conventional Commits with scopes (e.g. `feat(infra-db): …`). The pre-push hook runs oxlint.
- Work happens in feature branches, delivered as PRs to `main`. Never touch encrypted `.env*` files or `.env.keys`.
- Don't run `bun run customize` or `rename`. Those are template bootstrap tools.
